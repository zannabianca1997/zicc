`README.md` are sparse around the repo. They are **human oriented** and as such
are principally edited and read by humans.

When creating one, create a simple one with a title and a one-line description:
```markdown
# Example readme

... Basic explanation of the directory ...
```

When changing the public api, or making large changes to the project, check the
`README.md`s for inconsistences, and eventually report them to the user,
proposing to fix them yourself. If given the go-ahead, **only then** proceed.
